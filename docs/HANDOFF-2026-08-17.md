## 3. 已实现的关键机制

### 3.1 E 阶段（近源采集）
- hooks 8→13：新增 `pre_api_request` / `api_request_error` / `on_stream_start` /
  `on_stream_delta` / `on_stream_end`（`__init__.py::register`）。
- `post_api_request` 为**每次 API 调用**级主写点（比 turn 级 post_llm_call 更近源）：
  - 拆块写 `turn_stream`：`THINKING`（decide）/ `AGENT_REPLY`（decide）/
    `tool_call_request`（act）/ `tool_call_result`（observe）；
  - 每行带 `request_id/provider/model/reasoning_chars/text_chars/result_chars/
    error_text/is_fin/metadata_incomplete/block_type/ooda_stage`。
- 流式旁路：`on_stream_*` 只做内存计数（`plugin._stream_pending`），
  `on_stream_end` 一次性 UPSERT 补丁 `llm_calls`（统计列 MAX 合并）；
  与 `post_api_request` 无顺序保证，但 UPSERT 保证不丢。
- 注意：`plugins.stream_reasoning_deltas` 默认 false 只影响流式 delta；
  reasoning 全量仍从 `post_api_request.assistant_message` 提取（`ca/meta_marker.py`）。

### 3.2 存储（`ca/store.py`）
- turn_stream v7 增量列：旧库 `_migrate_turn_stream_v7` 幂等 ALTER（user_version=1）。
- 新表：
  - `llm_calls`：`UNIQUE(session_id, request_id)`，retry latest-wins；usage 全量 JSON、
    finish_kind/duration/failure、stream chunk 计数。
  - `think_trace`：`UNIQUE(session_id, turn, seq)`，只存 `raw_len` 指针 + preview≤160；
    reasoning 全文留在 turn_stream THINKING 行（L2）。
- `write_turn_v5` 核心列比较已扩展到 v7 新列（旧行 NULL 补齐），
  重放仍保护已回填的 Fct/Hdl。

### 3.3 think（`ca/think_collect.py` + `ca/meta_marker.py`）
- 卡类型：`decision`（reasoning+tool_calls，任意长度）；
  `orient`（事务内首段无工具 think，**零门槛**）；`conclusion`（fin 轮 ≥800 字/
  修正词表/工具错误）。
- reasoning 提取顺序：`provider_data.reasoning_content` → 顶层 `.reasoning` →
  `reasoning_details`/`codex_reasoning_items`/`codex_message_items`/
  `anthropic_content_blocks` → 内联 `<think>` 标签兜底；双源去重合并，不把
  content 冒充 reasoning。
- 历史数据边界：v6.1 之前纯对话首轮 think 未落盘，**不可恢复**；旧 thought 行
  （工具轮）可回填 decision 卡（脚本待写）。

### 3.4 Fct（`ca/fct_multi_affair.py` + `ca/f_stage.py` + `ca/prompts.py`）
- 输入：事务帧 `[ooda_stage|block_type]` + 代码筛选 think 卡
  （当前 turn、orient 优先、max 2 卡、每卡 800 字、总预算 1600）。
- 输出：`FCT_GENERATION_PROMPT_MULTI_AFFAIR` 要求
  `{"affairs":[{hdl,turns,ooda{四段},changes[{stage_tag,core_change}]}]}`。
- 解析：`parse_fct_multi_affair`（剥围栏/JSON 对象/逐字段校验）→
  `flatten_affairs_to_legacy` 扁平出 legacy changes/core_change/四段字段；
  `affairs` 原样存入 Fct JSON。
- 降级链：multi-affair JSON → legacy `parse_v1_markdown_xml` →
  截断 partial JSON → `PAIR_PATTERN` → pending backfill。
- 开关：`CA_FCT_MULTI_AFFAIR_ENABLED=1`（0 整体回退旧 prompt/解析）。

### 3.5 Strand（`ca/store.py::collect_turn_fcts` + `ca/topic_summary.py`）
- `collect_turn_fcts` 透传 Fct `affairs[]`（含 hdl/turns/ooda/changes）。
- `_format_turns_for_prompt`：有 affairs 时渲染
  `事务清单（编号即候选 strand）：1. hdl / 2. hdl` + 每事务 ooda/changes；
  有 affairs 即跳过 legacy changes 重复输入（效率优先）。
- `TOPIC_SUMMARIZE_PROMPT` 新增规则：编号即候选 strand，优先跨轮合并、
  不凭空发明/重命名；只有编号内明显含两条工作线才再拆。

## 6. 风险与已知坑

- `on_stream_*` 异步 worker 与 `post_api_request` 同步 invoke **无顺序保证**——
  一律走 `llm_calls` UPSERT，不要改成纯 UPDATE。
- stream 回调必须 `**kwargs`（Hermes worker 不做签名裁剪）。
- `post_api_request.usage` 无 `completion_tokens`：canonical summary 用
  `output_tokens`；turn_stream 旧列映射 `usage_completion_tokens=output_tokens`。
- reasoning 原文只落 per-session DB（turn_stream THINKING 行），不复制进共享
  DB/OV；preview≤160。
- Fct multi-affair 与 legacy 双写是过渡态：topic_summary 已优先消费 affairs，
  但 Fct JSON 里仍保留扁平字段供 A-stage/旧脚本；下一步按 §4.1 单一化。
- 旧库迁移幂等但只补列：`PRAGMA user_version` 已置 1，新表在 per-session DB，
  未来迁移不要动旧 11 表语义。
