### P0-2 [BUG-11] refinement update_reality 传 Connection → AttributeError（中，实测复现）

- **文件**: `ca/refinement.py:387-393, 566-571` + `ca/store.py:390-393`
- **证据**: `update_reality(..., db_path=conn)` 传 sqlite3.Connection，`_get_topic_conn` 对 db_path 调 `p.resolve()`。实测：`AttributeError: 'sqlite3.Connection' object has no attribute 'resolve'`。两处调用点的 conn 均来自无参 `_get_topic_conn()` = 默认路径。
- **建议修复**（二选一，推荐 A）:
  - A（最小）：refinement.py 两处 `db_path=conn` 改为不传（update_reality 内部走默认路径，`_TOPIC_STORE_CACHE` 缓存复用同一连接，语义等价）。
  - B（防御）：`_get_topic_conn` 开头加 `if isinstance(db_path, sqlite3.Connection): return db_path`（需确认 import；注意绕过缓存但传入的 conn 已是有效连接）。
  - 推荐 A+B 同做：A 修当前调用，B 防未来误用。
- **验证**: 复现脚本 `update_reality(reality_id=1, db_path=conn)` 不再抛 AttributeError；`pytest tests/ -q` 全过。

### P1-1 [D1 最终修正] tail-protection 恢复「固定最后 2 轮」原始实现（用户裁定 2026-08-08，两次纠正）

- **用户裁定（第二次纠正，最终）**：**「+ 超预算时向前扩展」是错误设计**——动态扩展会使 conv_history 内容随会话长度变化，破坏前缀稳定性，进而破坏云端 prompt 缓存命中率。**「保护后 2 轮正常对话」是正确设计**，恢复原始硬编码实现（75b55d1^）。
- **已执行（tester）**：

  2. `docs/wiki/decisions/13-tail-protection.md`：选定改为「保护最后 2 个 user 轮」，删除「预算扫描/扩展」描述，注明错误设计回退原因（缓存命中）。
  3. `ca/config.py` `PROTECT_TAIL_TOKENS` 加注释：语义 = 话题块 token 保护（TOPIC_PEAK_TOKEN 承接），当前无消费点，不参与尾部保护区。
  4. `ca/settings.yaml` 注释修正（解除与决策 13 的错误关联）。
- **语义澄清（用户指正）**：`protect_tail_tokens`（20000）与 `topic_peak_token`（20000）同值同思路——**话题块 token 保护/强制切分过长主题块**（`topic_manager._apply_water_pressure` 水位满压消费 TOPIC_PEAK_TOKEN），不是 tail 扩展预算。第一轮审计 D1 把「PROTECT_TAIL_TOKENS 无消费点」曲解为「tail 设计未实装」→ 引入预算扫描（错误方向）；实际 tail 保护区本就固定 2 轮（正确）。
