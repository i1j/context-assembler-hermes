# CR-005: `_compute_centroids` session_id 断链 + Fct 空值保护 (2026-06-20)

---
**父节点:** [[R-000]]
---

**Parent:** R-000

**Problem:** `SQLiteStore` 无 `session_id` 属性 → `_compute_centroids()` 中 `self._store.session_id` → `AttributeError` → 被 `except Exception: continue` 吞掉 → 所有 centroid 恒为 None → 话题降级机制完全失效，TopicGrade 全线 REL fallback，实际不降级

**Root cause:** `TopicGradeManager` 初始化时未传入 session_id，store 也未提供

**Fix:** 4 处修改：
1. `ca/store.py`: 新增 `self.session_id: str = self._db_path.stem` — 每个 DB 文件只服务一个 session，文件名即 session_id
2. `topic_manager.py`: 回退 `_session_id` 参数，`_compute_centroids` 用 `self._store.session_id` 获取
3. `plugins/ca_assembler/__init__.py`: 回退 `TopicGradeManager` 初始化，不再传 `session_id` 参数
4. `ca/__init__.py`: 四类行(queue 填充) `fct or ""` → `fct` 且判断 `if ... and fct`，防 Fct=None 时写入空串替换原文

**Evidence:** ca/store.py; topic_manager.py; __init__.py; plugins/ca_assembler/__init__.py (commit working tree 2026-06-20)

**Tests:** tests/unit/test_topic_manager.py (99 → 99 passed); tests/stage/test_a_stage.py + test_a_stage_topic_aware.py (134 passed); 全量 287 passed

**测试体系漏洞（同一事故揭示）:**
1. `mock_store.session_id = "test"` workaround 隐藏在 8 处测试中 — 所有调用 `_compute_centroids` 的测试都手动给 store 加了不存在属性，bug 被掩盖
2. 阶段测试全 mock `_topic_mgr` — `TestACTGrade`/`TestRELGrade`/`TestFARGrade` 测的是替换逻辑而非定级管线
3. 缺全链路集成测试 — 没有从 `pre_llm_call_v5` → `topic_mgr.detect()` → `grade_on_switch()` → `_compute_centroids()` → `get_turn_grade()` → `_simple_mutation_mode_v5()` 完整跑通的测试
4. 缺 Store 接口契约测试 — 无 `assert hasattr(store, 'session_id')` 验证
5. `except Exception: continue` 过宽 — `topic_manager.py:504` 吞掉所有异常，便于 bug 藏身
6. 交叉验证审计只查名字 — 原 `cross_ref_wiki_audit.py` 只确认 test name → wiki decision point 存在（CR-007 重命名为 `test_cross_ref_wiki_audit.py` 并升级为 35 条 parametrized 运行时用例）

**后续修复:** GAP #2-6 已由后续会话修复（见 [[CR-007]]，GAP-11/12/13 状态）。
