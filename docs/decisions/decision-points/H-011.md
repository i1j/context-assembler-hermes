# H-011: state DB 污染切断 (v5.1)

**Context:** `post_llm_call` 共享 dict 在 A-stage 替换后被污染，同 turn 内下游消费读到篡改后内容

**Decision:** 注入前快照原始 content，替换完成后原地恢复。注入不影响同轮后续各钩子的原始数据读取

## 后续发现 (v5.10 后期, [[INC-004]])

`conv_hist[:] = [{**m} for m in _backup]` 作为恢复手段带来了另一个问题——**创建全新 dict 对象**
破坏了 Hermes `_flush_messages_to_session_db()` 的 `id()` 去重机制，导致 state.db 每轮重复写入所有消息。

**修复:** `_full_backup` 直写 state.db，不再通过 `conv_hist[:]` 做 restore。`id()` 去重正常工作。

**Evidence:** changelog v5.1, 2026-06-11; [[INC-004]]; [[C-027]]
