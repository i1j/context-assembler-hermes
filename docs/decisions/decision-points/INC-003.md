# INC-003: 286K 会话篡改事故 — tail→turn 映射 bug + 配置断链 + Fct 语义丢失

---
**父节点:** [[R-000]]
---

**Parent:** R-000

**Impact:** 助理将用户项目文档错误放入 OV memories, 用户多次纠正被 Fct 摘要篡改为"已实施"

**Overall cause:** 6 层互锁失效叠加 (分析: 20260610-ca-mutation-thinking-rootcause.md)

### 失效层① — 上下文 > CA 限制 (结构性)

286K tok >> CA 200K 上下文限制 → 大部分轮被 topic grading 降级。T38-T41 全在降级区。架构级限制, 当前无直接修复。

### 失效层② — tail→turn 映射 bug (已修复)

`_compute_tail_start()` 与 `in_tail` 过滤逻辑不一致 → T33-T41 被排除在 tail 区外。

**Fix:** 替换为基于 `_turn_index` 的轮索引计算 (2026-06-10 已实施):
```python
_tail_start_turn = min(messages[_i].get("_turn_index") for _i from tail_start)
in_tail = (_tail_start_turn > 0 and turn >= _tail_start_turn)
```
不扩大 tail 预算, 仅修正分配正确性。

### 失效层③ — 快速用户插入正反馈

用户连续 4 轮插入纠正 → 每轮工具输出臃肿(52K+74K) → 上下文更大 → 降级更狠。正反馈循环: 纠正→工具输出→上下文膨胀→降级→错得更远。架构级问题, 无单独修复。

### 失效层④ — 用户强制插入检测 (待实施)

Hermes 工具循环中用户插入中断 → CA 不知中断。中断轮应优先保留 Elm, Fct 加 `[INTERRUPTED]`/`[CORRECTION]` 标记。检测逻辑: 两个 user 消息间, 前一个 assistant 无 text → 被中断。

### 失效层⑤ — Fct 语义篡改 (架构级)

Fct 将"是不是拆成wiki页面"摘要为"已拆分为..."——增量 OODA 设计天然偏好状态快照而非对话意图。

### 失效层⑥ — `_assemble_status=1` 导致轮消失

T41 完全从 turn_plan 消失: status=1 → `_build_messages_from_plan()` skip。

### 附加问题 — config.yaml 配置链断裂

config.yaml 设 `protect_tail_tokens: 20000` 但 CA 读 env var (`CA_PROTECT_TAIL_TOKENS`), 默认 10000。

**Decision:** 不修复。20K char≈5K tok 的默认平衡点是信息密度最优值。
