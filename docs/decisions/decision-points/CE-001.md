# CE-001: 帧扫描获取 agent 引用
> **⚠️ 已废弃 — ContextEngine 管道替换方案已在 v5.10 移除。CA 不再接管 `_compress_context`/`_persist_session`，改用 `pre_llm_call`/`post_llm_call` 8 钩子 (P-004)。**


---
**父节点:** [[CE-000]]

## 问题

`_setup_context_engine_hooks()` 需要 `agent` 对象才能替换 `agent._compress_context`。CA 插件 hook 回调 `_on_pre_llm_call(**kwargs)` 只获得 `session_id`、`conversation_history` 等，不包含 agent 引用。`_on_session_start` 也只有 `session_id`、`model`、`platform`。

## 尝试过的方案

| 方案 | 结果 | 原因 |
|------|------|------|
| `get_plugin_manager()._cli_ref.agent` | ❌ `_cli_ref` 为 None | `discover_plugins()` 早于 HermesCLI.__init__，虽然 HermesCLI 最终设置了 `_cli_ref`，但在第一轮 `_on_pre_llm_call` 时仍未就绪 |
| `_manager_ref._cli_ref.agent` | ❌ 同上 | 与 `get_plugin_manager()` 同一对象 |
| 等待 `_cli_ref` 后续轮就绪 | ⚠️ 可能可用但不可靠 | 依赖 CLI 初始化时序，gateway 模式不同 |

## 决策

采用 `sys._getframe()` 调用栈扫描。`_on_pre_llm_call` 被调用时调用栈包含 `build_turn_context(agent, ...)` 帧，该帧的 `f_locals` 中有 `agent` 变量。

```
_on_pre_llm_call(**kwargs)    ← sys._getframe(0)
  invoke_hook(...)             ← frame 1
  _invoke_hook(...)            ← frame 2
  build_turn_context(agent,...)← frame 3 — f_locals["agent"] 在这里
```

### 实现

```python
_f = sys._getframe()
while _f is not None:
    _a = _f.f_locals.get("agent")
    if _a is not None:
        _agent = _a
        break
    _f = _f.f_back
```

### 风险

- 依赖 CPython 实现细节（`sys._getframe` 不是所有 Python 实现都支持）
- 在 gateway/TUI 模式下调用栈可能不同
- 性能开销极小（帧扫描一般在 3-5 层）
