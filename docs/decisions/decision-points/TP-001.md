## 优点

- 增量分割：只扫描新 turn，不重建旧话题，性能好
- 三路检测互补：Jaccard + 强制短语 + 水位压力，覆盖语义渐变、显式切换、Jaccard 失效三种场景
- 水位压力不引入外部依赖：conv_hist 已在参数中，零额外 I/O
- 柔性切割：同线性的 Jaccard 跨阈值，不依赖随机数

## 约束 / 已知问题

- CJK 重叠在中文单字场景下准确率有限（单个字的重叠可能误判为话题延续）
- 强制短语依赖预定义列表，无法覆盖所有话题切换语言
- 话题分割的边界可能不等于 LLM 感知的话题边界
- 水位压力的精度依赖字符粗估（÷1.5），极端 CJK/代码比例下可能偏差 2 倍
- 工具密集会话中 conv_hist 总 token 增长快，peak=20K 会较早触发切割
- **Fct JSON 公共键名污染 Jaccard → 虚假延续**（2026-07-31 实测）：结构化键名 token（如 `core_change` 拆出的 {core, change}）被两段无关话题共享（"数据库设计" vs "Python优化"）→ j≈0.13 ≥ 0.04 链内阈值，误判为话题延续。与 CJK 单字重叠同源（结构性噪音 token 抬高 Jaccard）。本轮测试以强制分割短语绕开，未改分割逻辑。根治方向（独立优化点，需单排一轮）：Jaccard 计算前剥离 JSON 键名 / 结构噪音 token。
