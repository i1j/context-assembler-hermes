# R-002: CA-OV 分层架构 (2026-05-31)

**Context:** CA 作为 Hermes 上下文引擎产 Fct/Elm/Hdl，OV 作为长期记忆提供存储与语义检索。需要明确两层职责边界，防止功能重叠与数据不必要流动。

**Decision:**

### 三层分工

| 层 | 职责 | 数据 | 时机 |
|----|------|------|------|
| **CA 实时层** | 每轮产 Elm(原始消息)+Fct(OODA 5节)+Hdl(标题)，存 CA SQL | OODA 5节: 核心摘要/资源与观察/事实与约束/决策与结论/后续行动 | 每轮对话完成 |
| **CA commit 模块** | 只在合适时机将会话 Fct OODA 送入 OV，不送 Elm。Elm 只在 CA 是单源真相 | Fct OODA(不输 Elm) | 会话退出兜底 |
| **OV 空闲层** | 收到 OODA 后映射到 7 段 Working Memory，VLM 补 Errors/Issues 全局判断 | 自定义模板 → 7段 WM → 8类记忆 → 向量索引 | 空闲时 |

### 分阶段实施

- **P1（现状）**: OV 做 memory.provider+MCP, CA 做 context_engine, 加 ca_turn_lookup 工具
- **P2**: CA 检测话题切换时 commit OODA 给 OV
- **P3**: 话题摘要取代轮次摘要

### 约束

- 7 段标题保留（WM_SEVEN_SECTIONS 硬合约），内容装 OODA
- CA 不补错误/未决，交给 OV 全局判断
- 追溯原始事实找 CA Elm，OV 不存原始消息
- CA 是事实层(资源/约束/决策/行动)，OV 是判断层(错误、未决、全局状态)
