# INC-002: 早期部署三连故障 — A-stage 从未真正运行 (pre-`pre_llm_call` 时代)

---
**父节点:** [[R-000]]
---

**Parent:** R-000

**Impact:** CA Plugin 在生产路径上完全未生效 (test-report 2026-05-23)

**Context:** 当时 CA 的 A-stage 挂在 Hermes ContextEngine 协议的 `compress()` 方法上, 非 `pre_llm_call` hook

### Finding #1 — A-stage 挂错入口 (严重)

A-stage 挂在 `compress()` 而非 `pre_llm_call`, 导致汇编仅在 `prompt_tokens >= threshold_tokens` 时触发。大部分轮次不走汇编; 设计文档(3份)一致写 pre_llm_call, 代码未实现。

**Fix:** 改为 `pre_llm_call` hook 驱动 + `should_compress()=False` (见 [[C-025]])

### Finding #2 — compress()→assemble() 参数类型崩溃 (中)

`compress(messages, current_tokens=85000)` 将 int 传给 `assemble(user_input=str)` → `tokenise(int).lower()` → `AttributeError` → 被 try/except 静默吞掉。

**Fix:** 挂钩 pre_llm_call 后传入真正 user_message 字符串

### Finding #3 — context_length 未传 threshold 值 (建议)

Plugin 已计算 `threshold_tokens` 但未使用, 传给 assemble() 的是完整 ctx。`_available_budget()` 以完整 200K 而非 threshold 计算 → 预算偏大。

**Fix:** 改为 config.py 注入, `*0.95` 降为 fallback

### 综合

三项叠加 → CA 任何轮次都不走真实组装。这是 `should_compress()=False` + `pre_llm_call` hook 重构的直接触发原因。

**Evidence:** tests/docs/test-report.md (2026-05-23); changelog v4.3; changelog v4.3-selfcheck
