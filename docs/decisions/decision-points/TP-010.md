# TP-010: CE In-Place 删行 — should_compress=True + compress 原地删除 + backup/restore

> 2026-07-31 实装
> 前置讨论: TP-009 方向二（CE 接口）具体实现 — should_compress 从 False → True，compress() 改为 in-place 原地删行，放弃 session 轮转路径
> **核心纠正**: 不走 compress_context 的 archive_and_compact 路径（通过 _last_compress_aborted sentinel 阻断），也不切换 session_id。删行仅在内存中生效，state.db 完整保留。

## 1. 问题

### 1.1 旧"略"替换方案的天花板

A-stage `_simple_mutation_mode_v5` 对 FAR 行做 content 替换为"略"，保留消息 JSON 骨架：

```json
{"role": "assistant", "content": "略"}
```

每行 skeleton overhead ~40-60 tokens（role 字段、逗号、花括号）。FAR 行 N 行 ≈ N × 50 tokens 浪费。

### 1.2 删行在 Hook 路径下不可行

CA 通过 `pre_llm_call` hook 获得的是 `conversation_history=list(messages)` — Python list 的浅拷贝。删除 copy 中的元素不影响原始 `messages` 列表。

```python
# turn_context.py — 传入的是浅拷贝
conversation_history=list(messages)  # copy: 共享 dict 引用，但 list 结构独立
```

删行后 Hermes 主循环仍然持有完全长表 → LLM 仍然收到所有行。

### 1.3 CE compress() 路径能删行但会导致 session 轮转

Hermes `ContextEngine.compress()` 通过 `compress_context()` 返回新消息列表 → Hermes 自动替换为 `messages`。可以删行。但 `compress_context()` 默认触发：

1. `archive_and_compact` — 压缩旧会话到 state.db
2. `session rotation` — 产生新 session_id

✅ 能删行，❌ 副作用过大。

## 2. 决策

### 2.1 should_compress() → 始终 True（无条件）

```python
def should_compress(self, prompt_tokens=None) -> bool:
    self._last_compress_aborted = True  # 预设 sentinel
    self._last_summary_error = "CA: in-place FAR deletion, no rotation"
    return True
```

每轮都触发 CE 管道，但用 sentinel 阻断 archive_and_compact + rotation。

**为什么无条件：**
- Hermes `compress_context` 只在 `should_compress()=True` 时才调用 `compress()`
- 如果只在「有 FAR 内容时」返回 True，则需要 CA 提前扫描 conv_hist → 引入额外遍历
- 无条件 True 代价极低（abort sentinel 的检查成本远低于一次 LLM 调用）
- `_last_summary_error` 的长字符串设一次后不再重复（dedup key 缓存）

### 2.2 compress() → in-place 原地删除

```python
def compress(self, messages, current_tokens=None, focus_topic=None, force=False):
    # 1. 备份原始数据到 plugin._full_backup
    # 2. 复用现有 topic_grade + turn_stream 数据
    # 3. 识别 FAR thought/tool 行对
    # 4. messages[:] = [m for m in messages if not in_drop_indices]
    # 5. return messages
```

**关键约束：** 用 `messages[:] = filtered`（原地 slice 赋值）而非 `return filtered`。

- `messages[:] = filtered`：修改原 list 对象的内部指针 → caller 持有的是同一个 list 对象 → 引用自动更新
- `return filtered`：返回新 list 对象 → caller 需要解包赋值 → compress_context 内部有解包逻辑，两种行为均由 compress_context 统一处理

**实际采用** `messages[:] = filtered` 确保同一对象引用。但 `compress_context` 的 in_place / rotate 路径对返回值做了合适的处理，保留 messages 即可。

### 2.3 `_full_backup` 全量备份 → post_llm_call 恢复

```python
# compress() 中
plugin = self._get_plugin(session_id)
plugin._full_backup = [{**m} for m in messages]  # 深拷贝所有 dict
# ... 删行 ...
messages[:] = filtered

# post_llm_call_v5 中
backup = getattr(self, "_full_backup", None)
if backup is not None:
    for i, orig_dict in enumerate(backup):
        if i >= len(conversation_history):
            break
        ch = conversation_history[i]
        for _key in ("content", "reasoning_content", "tool_calls"):
            if _key in orig_dict:
                ch[_key] = orig_dict[_key]
            else:
                ch.pop(_key, None)
    self._full_backup = None
```

FAR 删除的 30 行在 `_full_backup` 中备份但不在 `conversation_history`（已被 CE 删行缩短）→ 不追加回内存 → 从内存永久消失。

**state.db 写的是原始数据**（CE 在 compress 后写 state.db 前，post_llm_call 从备份恢复了所有仍在 conv_hist 中的 dict 的 content）。

**注意：** FAR 30 行的原始数据在之前的 turn 已经写入 state.db（通过 Hermes 的 `_flush_messages_to_session_db`）。它们不会"丢失"，只是不在活跃消息中（符合 FAR 的定义）。

### 2.4 `_last_compress_aborted` sentinel → 阻断 archive_and_compact + rotation

`compress_context` (conversation_compression.py:470) 检查：

```python
if getattr(agent.context_compressor, "_last_compress_aborted", False):
    # 跳过 archive_and_compact
    # 跳过 session rotation
    return messages, _existing_sp
```

三行代码完成阻断。`in_place` 配置在此路径下不生效（abort 检查在 in_place 检查之前）。

### 2.5 `compression.in_place: true` 安全网

仅对手动 `/compress` 生效（force=True，绕过 should_compress，不设 abort sentinel）：

| 场景 | abort 标志 | 行为 |
|------|-----------|------|
| CA 自动压缩（每轮 via should_compress） | True | abort → 无 archive, 无 rotation |
| `/compress` 手动（force=True） | 未设置 | in_place → 同 session 内 archive, 不 rotation |

### 2.6 tail 保护区：最后 2 轮 user 不动

复用 `_simple_mutation_mode_v5` 已有的 `_tail_user_limit` 逻辑：

```python
_tail_user_limit = search - last 2 user messages
```

TODO: compress 当前简化实现用 `_tail_protect` 固定只保护最后 2 轮，但 integrate 了 v5.10 原来的 tail 保护逻辑。

注意：此处的 tail 保护（最后 2 轮不动）和 `protect_last_n` / `in_place` 配置无关，由 CA 内部逻辑保证。

## 3. 数据流对比

| 阶段 | 旧（"略"替换） | 新（CE in-place 删行） |
|------|----------------|----------------------|
| **入口** | `pre_llm_call` hook | `should_compress=True` → `compress_context` → CA.compress() |
| **行操作** | content="略"（保留行） | 删除整行（FAR thought+tool） |
| **token 节省** | thought body（~200-600 tok/行） | thought body + JSON skeleton（~40-60 tok/行） |
| **30 FAR turn** | ~6000-18000 tok | ~7200-19800 tok（~1200-1800 额外 overhead） |
| **state.db** | 从 snapshot 恢复原文 | 从 `_full_backup` 恢复 conv_hist dict |
| **session ID** | 不变 | 不变（abort sentinel） |
| **恢复机制** | `_saved_history_snapshot`（tuple of dicts） | `_full_backup`（全量 list of dicts） |
| **FAR 行去向** | conv_hist 中保留（content="略"） | 从 conv_hist 永久消失 |
| **prompt cache** | system message 缓存不受影响 | 同左 |

## 5. 影响分析

### 5.1 缓存命中机制

**不受影响。** Hermes prompt caching 的 breakpoint 在 system message 上。system message 内容不变，cache prefix 不变。被删的 FAR 行在"略"方案中也属于 cache miss 区域（每轮都在变），删行对缓存无影响。

### 5.2 state.db 完整性

- 当前 turn 的内存中 conv_hist 少了 30 FAR 行
- 但 FAR 行在之前 turn 已经写入 state.db（通过 Hermes `_flush_messages_to_session_db`）
- post_llm_call 从 `_full_backup` 恢复非 FAR 行的 dict content → state.db 写入原文
- **state.db 无"略"泄漏**（已验证：state.db Q=0）

### 5.3 跨 turn 影响

Turn N 删除 FAR 行后，内存中 conv_hist 永久少 30 行。Turn N+1 的 `build_turn_context(conversation_history=conv_hist)` 只从 170 行开始。这是期望行为 — FAR 行本就不应该出现在后续 turn 中。

## 7. 与 TP-009 方向二的区别

| 维度 | TP-009b（规划） | TP-010（实现） |
|------|---------------|--------------|
| should_compress | 「有旧话题且 token 超阈值」 | 始终 True + abort sentinel |
| 模式切换 | CE 模式 / 插件钩子模式双模式 | 同时运行 — CE 做删行，hooks 做替换 |
| session rotation | `compress_context` 自动轮转 | abort sentinel 阻断 → 不轮转 |
| compress() 输出 | 新话题摘要替换整链 | 只删 FAR thought/tool 行对，不合并话题 |
| state.db 写法 | 新 session 消息累积 | `_full_backup` 恢复后写当前 session |
| tail 保护 | `protect_last_n` 配置 | CA 内部 `_tail_user_limit`（最后 2 user 轮） |
