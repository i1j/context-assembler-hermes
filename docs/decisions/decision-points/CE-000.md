# CE-000: 接管 Hermes compress engine 管道
> **⚠️ 已废弃 — 被 [[TP-009]] 取代。旧 monkey-patch 方案 (`_compress_context`/`_persist_session` 接管) 改为标准 `ContextEngine` ABC 实现。CA 通过 `context.engine: ca_assembler` 注册为压缩引擎，经 `compress(messages)` 接口获得消息列表完全操控权。**

## 背景

CA 插件当前通过 `pre_llm_call` hook 用共享 dict 突变注入内容。每种消息保留 Hermes 原始 dict 的 tool 骨架（tool_call_id 等字段每行约 32 tok），造成 token 浪费。更好的方式是直接接管消息列表构造，传给 LLM 一个干净版。

Hermes 在 `turn_context.py:296` 调用 `agent._compress_context(messages, ...)` 返回短表。返回值通过 `=` 赋值给 `messages` 局部变量 → `_ctx.messages` → 进入 LLM 输入。这是 Hermes 自身压缩引擎的注入路径。

## 决策

CA 替换 `agent._compress_context` 方法，接管消息列表构造权。同时替换 `agent._persist_session` 以确保 state.db 写入原始长表。

### 三线替换

| 替换对象 | 职责 | 红线约束 |
|---------|------|---------|
| `agent._compress_context` | 接 messages → 存原始快照 → 返回组装短表 | 不调 `end_session/create_session`，不改 `session_id` |
| `agent._persist_session` | 拦截写入 → 用原始快照 + LLM 新回复重构长表 → 写 state.db | 不污染 state.db |
| `agent.context_compressor.should_compress` | 恒 True + 零保护长度 | 保证每轮触发 |

### 红线

1. **不动 Hermes 源码** — 纯 `对象属性 = closure` 实例覆盖
2. **不污染 state.db** — `_persist_session` 包装器在写入前将短表恢复成 `originals + appended` 长表
3. **不替换 session** — 不调 `end_session()`/`create_session()`，`session_id` 不变
