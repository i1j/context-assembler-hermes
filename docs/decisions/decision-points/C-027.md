# C-027: post_llm_call save/restore 快照机制 (PR3)

**父节点:** [[C-010]]

**Parent:** C-010

**Context:** replace 模式 mutation 就地修改 conversation_history → 需恢复原始消息供下一轮 C-stage
快照机制: `_saved_history_snapshot` (全量 clear+extend)，按内容恢复，不按索引。

**Decision:** pre_llm_call 保存 `_saved_history_snapshot = [{**m} for m in history]` → post_llm_call 全量恢复

**Design note:** 此为 v5.0 方案。E-stage 设计（[[E-stage-000]]）称「不再需要 save/restore snapshot」，
但 E-stage 尚未完全接管 A-stage 输出通路——`_simple_mutation_mode_v5` 仍 mutation `conversation_history`，
因此 snapshot 当前仍为必需。如果今后重构 A-stage 不 mutation conv_hist，C-027 可整页删除。

## 已发现缺陷: `conv_hist[:]=_backup` 破坏 Hermes `id()` 去重 ([[INC-004]])

`conv_hist[:] = [{**m} for m in _backup]` 创建**全新 dict 对象**，切断了与 `conversation_history`
中原始 dict 对象的引用关系。Hermes 的 `_flush_messages_to_session_db()` 用 Python `id()`
跟踪已写入 state.db 的 dict 对象——全新 dict 导致 `id()` 全部不匹配，每轮所有消息重写一次。

**已修复:** `_full_backup` 仅作 sentinel，post_llm_call 仅清掉它，不再写 state.db。
所有原始数据（包括被 A-stage 删掉的 FAR 行、被替换为 Hdl 的 content）均在 compress 之前
由 `_flush_messages_to_session_db` 的正常流程写入过 state.db。详见 [[INC-004]]。

## 数据流（修复后）

| 路径 | 内容 | 去重机制 |
|------|------|----------|
| `_flush_messages_to_session_db` | 正常对话流程中的全部消息 | `id()` 去重，每轮只补增量 |
| `_full_backup` | **不再写 state.db**，仅作 compress sentinel | — |
