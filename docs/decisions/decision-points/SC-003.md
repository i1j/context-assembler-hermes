# SC-003: 惰性迁移 — 旧 DB readonly + 严格版本守卫

---
**父节点:** [[SC-001]]
---

**Parent:** SC-001

**Context:** 避免大规模生产环境下的迁移风险; 旧数据通过不同 ORDER BY 重建消息顺序

**Decision:** 旧 schema DB 保持 readonly, 正常读取排序, 不自动迁移; 误以 writable 打开 v4 DB 时 raise RuntimeError

**Evidence:** tool-turn-refactor-technical-plan.md §1.3; pr1-review-decisions.md (34 items, 33 adopted)

**Detail:** version v4→v5 迁移只升版本号不改结构 → 必须 readonly 防止静默破坏
- `_check_schema` 加 `if not self._readonly and current_ver < 5: raise RuntimeError`
- `_migrate(4)` 加 writable guard
- role 映射: v4 `turn_type='dialogue'` → v5 `role='user'` (对话轮首行恒为用户)
- turn_plan PK 与 turn_cache 一致 `(session, turn, api_call_count, seq_index)`
