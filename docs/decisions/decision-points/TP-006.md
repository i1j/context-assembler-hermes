# TP-006: 水位压力 (water_pressure) — 长对话 Jaccard 柔性扣减

---
**父节点:** [[TP-001]]
---

**Parent:** TP-001

**Decision:** conv_hist 总 Token 超过阈值后线性扣减 Jaccard，抑制长对话晚期话题误合并。选用 conv_hist 总 token（字符÷1.5 粗估）做信号源，窗口 6K-20K，线性柔性切割，不引入随机数。

**Evidence:** topic_manager.py L424-L448 (`_apply_water_pressure`) (tester profile); config.py L171-L175

**Tests:**
  - `tests/unit/test_topic_manager.py` — `TestWaterPressure` (4 条路径: 不触发/低/中/高)
  - `tests/stage/test_a_stage_topic_aware.py` — 集成验证

## 背景

长对话中 Jaccard 匹配随话题累积文本增长而逐渐失效。25 轮后 `_topic_text_profiles[tid]` 累积到几万字，任意新输入都有 ≥2% 字符重叠，Jaccard 永不 miss，话题永不分裂。需要一个正交信号兜底。

## 信号选型

| 信号 | 开销 | 问题 |
|------|------|------|
| 轮数 | 零 | 无法覆盖单轮大量内容场景 |
| Elm 字符累积 (len profile) | 零 | 只算 user 文本，工具/assistant 不计 |
| **conv_hist 总 token（选定）** | 零，参数已有 | 天然涵盖全部内容 |

### 为什么不采用其他方案

| 方案 | 原因 |
|------|------|
| 纯轮数 | 单轮长消息（代码审查 5K chars）不会触发，但实际内容已很大 |
| 精确 tokenize | 性能开销大，且以最后防线定位不需要高精度 |
| 随机数概率切割 | 「对程序就是概率」体现在 raw_j 随输入变化自然跨阈值，不需要硬随机 |

## 公式

```python
peak = TOPIC_PEAK_TOKEN          # 20K — 满压点（配置）
start = int(peak × 0.30)         # 6K — 起始点（内部推算）
penalty = 0.30                   # 满压扣减值（内部常量）

progress = clamp((total_tokens - start) / (peak - start), 0, 1)
effective_j = raw_j - progress × penalty
```

**Detail:**
- `_apply_water_pressure(raw_j, total_tokens)` → 扣减后 effective_j
- total_tokens ≤ start → 不扣减
- total_tokens ≥ peak → 满扣 `_INTERNAL_PENALTY=0.30`
- start < total_tokens < peak → 线性插值扣减
- 扣减下限 = raw_j - 0.30（可能为负 → 不触发合并）
- Config.TOPIC_PEAK_TOKEN 默认 20000, env `CA_TOPIC_PEAK_TOKEN`
- `_INTERNAL_PENALTY = 0.30` 硬编码内部常量，不暴露给用户配置

## 窗口效果（peak=20K）

| total_tokens | progress | effective_j (raw_j=0.04) | 行为 |
|---|---|---|---|
| ≤ 6K | 0 | 0.04 | ❌ 不变 |
| 10K | 0.29 | 0.031 | 几乎不变 |
| 14K | 0.57 | 0.023 | 摇摆（依赖本轮输入变化自然跨阈值） |
| 17K | 0.79 | 0.016 | ✅ 大概率切 |
| 20K+ | 1.0 | 0.01 | ✅ 必切 |

## 字符 → Token 估算

`÷1.5`：CJK 文本约 1.2 chars/tok，工具 JSON 约 3 chars/tok，综合取值 1.5。`conversation_history` 包含 system + 所有历史轮（已被 CA 替换为 Fct）+ 当前轮 user Elm。零额外 I/O。

## 验证结果

51 轮工具密集型 session 验证：
- 第 3 轮 cum_tok=548（未到窗口起点 6K），不施压
- 第 4 轮 cum_tok=18,156（progress=86.83%），effective_j=-0.22，必分
- 第 5+ 轮全部满压

纯对话场景（无大工具输出）下，15-30 轮达到 6K-20K 窗口。
