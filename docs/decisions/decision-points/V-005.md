# V-005: 工具行 content 清空

---
**父节点:** [[V-001]] Replace/Append/Off
**关联:** [[P-006]] bg_review 内容清空
---

**Parent:** V-001

**Decision:** CA replace 模式 mutation 中，工具行 content 被替换为单空格 `" "`。原因：`conversation_history = list(messages)` 浅拷贝无法物理删除行（`del` 只删拷贝），但共享 dict 引用使 `content` 原地修改传播回 `messages`。

**Context:** 94 条 tool 行，原始 content 共 340K chars (~85K tok)。清理后保留 JSON 骨架每行 32 tok（cl100k_base 编码实测），其中：
- tool_call_id 值：19 tok（如 `call_00_U4quDyOgdzx0wdqUNKyG4404`）
- JSON 固定结构：13 tok（`{"role":"tool","tool_call_id":"` + `","content":"` + `"}`）
- content `" "` 与 `""` 差异：0 tok（单空格被合并入尾部 token ` "}`）

**Total overhead:** 94 行 × 32 tok = ~3K tok，较原始 85K tok 节省 ~97%。

**Alternatives considered:**
1. Deep copy + replace conv_h — 破坏 shared dict 引用，post_llm_call 无法恢复
2. state.db 快照 + 整体替换 — 后续迭代（需评估 SessionDB 连接）

**Limitations:** 无法消除 32 tok/行的结构 overhead。tool_call_id（19 tok）必须保留以匹配 assistant 的 tool_use 引用。JSON 外壳（13 tok）必须保留以构成合法 API 消息格式。

**Implementation:** `plugins/ca_assembler/__init__.py` — `_mutation_mode()` mutation 循环中 `outcome == ""` 分支：`msg["content"] = " "`。

**Evidence:**
- `docs/debug/debug-20260612-tool-row-removal-gap.md` (2026-06-12, 94 rows 340K chars → 94 chars)
- tiktoken(cl100k_base) 实测：32 tok/行，`" "` vs `""` 无差异
- state.db 通过 snapshot 恢复原始 content，不受清理影响
