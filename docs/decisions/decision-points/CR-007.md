# CR-007: 断路器函数缺失 — TP-008 误删 + 双重 DOA (2026-06-20)

---
**父节点:** [[R-000]]
---

**Parent:** R-000

**Context:** commit `2c4e34b` (TP-008 死代码清理) 将断路器文件的**实现**全部删除，但 plugin 中仍保留了调用点。

**Problem:** `__init__.py` 中 `_record_success()` / `_record_failure()` 等 8 个断路器函数从未被实现。

**Root cause — 生产代码：**
TP-008 清理了以下 8 个函数约 90 行：
| 函数 | 作用 |
|------|------|
| `_state_file_path()` | 返回 `~/.hermes/.ca_assembler_state_{PID}.json` |
| `_read_state()` | 读取断路器状态文件 |
| `_write_state()` | 写入断路器状态文件 |
| `_record_failure()` | 递增失败计数，3 次后跳闸 1h |
| `_record_success()` | 清零失败计数 |
| `is_available()` | 检查是否已跳闸 |
| `_cleanup_stale_state_files()` | 清理过期状态文件 |
| `_pid_exists()` | 检查 PID 是否存活 |

删除后保留了 3 个调用点：
- `on_session_start()` L179: `_record_success()` → NameError → `_engine = None` → 后续 E-stage hooks 全跳过
- `on_session_start()` L173: `_record_failure()` → 同上
- `on_session_reset()` L209: `_record_success()` → 同上

**Root cause — 测试体系双重 DOA：**

| DOA# | 问题 | 影响 |
|------|------|------|
| 1 | `tests/plugin/test_plugin.py` 模块级 `is_available = _ca_plugin.is_available` → AttributeError | pytest 收集阶段崩溃，33 个测试从未执行 |
| 2 | `tests/audit/cross_ref_wiki_audit.py` 文件名不匹配 `test_*.py` 模式，目录无 `__init__.py` | 35 个交叉验证测试从未被收集 |

**为何未被发现：**
```bash
# 作者跑的是 --ignore 过滤的全量
pytest tests/ --ignore=tests/plugin   → 292 passed ✓（跳过崩溃路径）
pytest tests/                          → ERROR ❌（完整收集暴露崩溃）
# commit msg 虚报: "324 test passed" = 292(实际跑的) + 32(新文件里数的)
```

**Option A:** 删除调用点（接受无断路器保护）。**Option B:** 重新实现断路器（保持设计哲学）。**Choice:** B

**Fix:**
1. 重新实现全部 8 个断路器函数
2. 重命名 `cross_ref_wiki_audit.py` → `test_cross_ref_wiki_audit.py`
3. 补 `tests/audit/__init__.py`
4. 新增 3 个 DOA 自防御测试（`tests/audit/test_doa_self_defense.py`）
5. 新增预检脚本 `scripts/test-preflight.sh`
6. 新增运行包装器 `tests/run_ca_tests.py`

**Tests:** 全量 385 passed, 1 skipped（较之前 +78，其中 68 个从 DOA 恢复）

**Evidence:** plugins/ca_assembler/__init__.py (CR-007 修正后); tests/audit/test_doa_self_defense.py; tests/audit/test_cross_ref_wiki_audit.py (35 条 parametrized)
