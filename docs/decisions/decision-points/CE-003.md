# CE-003: restore-before-write 恢复长表写 state.db
> **⚠️ 已废弃 — ContextEngine 管道替换方案已在 v5.10 移除。CA 不再接管 `_compress_context`/`_persist_session`，改用 `pre_llm_call`/`post_llm_call` 8 钩子 (P-004)。**


---
**父节点:** [[CE-000]]
---

## 问题

CA 组装版是比原始消息列表短的**短表**。如果直接让 `_persist_session` 写入当前 session 的 state.db，state.db 会丢失原始数据（被组装版覆盖）。这与 compress engine 的做法不同——compress engine 通过 session 替换（关旧 session → 建新 session）保留两套数据。

CA 不能替换 session，所以采用相反的策略：**销毁前恢复**。

## 决策

在 `_persist_session` 写入前，用 `_saved_originals[sid]`（原始长表深拷贝）替换 `messages` 中的组装部分，保留 LLM 新回复。

### 数据流

```
pre_llm_call:
  messages = [sys, u1, a1, t1, ... uN]           ← 原始 12 条
  _saved_originals[sid] = [dict(m) for m in messages]  ← 深拷贝
  _saved_short_len[sid] = len(messages) = 12

  _compress_context 返回 short = [sys', summary, tail0]  ← 3 条
  messages = short                                  ← LLM 看到 3 条

工具轮:
  messages = [sys', summary, tail0] + [assistant, tool1, ...]  ← 新回复追加

_persist_session:
  appended = messages[12:]     ← 空的（短表只有 3 条，原 12 条不存在了）
  ─── 等一下！这个不work───
```

### 修正

上述数据流有一个根本错误：`_saved_originals[sid]` 存的是原始 12 条，但 `_persist_session` 时 `messages` 是短表 3 条 + 新回复。`messages[12:]` 会取到空列表。应为：

```
_persist_session:
  originals = _saved_originals.pop(sid)
  short_len = _saved_short_len.pop(sid)           # 这里是 12
  ──── 短表长度不是 12，是 3！────
```

**解决方案**：`_saved_short_len` 应该存**组装版本的长度**，而不是原始版本的长度。

实测验证：

```
初始化:
  messages (原始)  = [sys, u1, a1, ... uN]   ← len=12
  _saved_originals = 深拷贝原始
  _saved_short_len = 12   ← 原始长度（这是当前代码的行为）

但实际上 _saved_short_len 应该存短表长度！
```

等等——再看实际代码。`_ca_compress` 存的是：

```python
_saved_short_len[session_id] = len(messages)  # 这是原始长度
```

但 `_ca_persist` 需要的是短表长度：

```python
short_len = _saved_short_len.pop(session_id)  
# ↑ 这里拿到的是原始长度 = 12
appended = messages[short_len:]  
# ↑ messages 只有 3+新回复，messages[12:] 为空
```

**这确实是个 bug** — `_saved_short_len` 应该存短表长度而非原始长度。但空壳测试中这个 bug 没暴露，因为：

1. 首次压缩发生在 `turn_context.py:296`，`_ca_compress` 被调用时 `messages` 已经是原始 12 条
2. `_saved_short_len` = 12
3. 后续 `_persist_session` 时 `messages` 长度 = 3(短表) + 5(工具轮新回复) = 8
4. `messages[12:]` = 空 → `appended = []`
5. `full = originals + []` = 原始 12 条
6. **state.db 写入正确！但缺少了 LLM 新回复（assistant + tool 结果）**

**需要在空壳阶段修复**：`_ca_compress` 应该设 `_saved_short_len` 为短表长度（即 `len(return_value)`），而非原始长度。

## 修正

```python
def _ca_compress(messages, system_message, ...):
    ...
    _saved_originals[session_id] = [dict(m) for m in messages]  # 原始
    # 先记原始长度，等组装后更新
    _compressed_flag[session_id] = True
    
    # 组装完更新为短表长度
    assembled = (messages, system_message or "")  # 空壳期原样
    _saved_short_len[session_id] = len(assembled[0])
    
    return assembled
```

## 影响

空壳测试中检查 `_persist_session` 的 `originals=3` 实际为原始长度，而非短表长度。虽然 state.db 数据显示正确（原始数据完整），但 LLM 新回复丢失。
