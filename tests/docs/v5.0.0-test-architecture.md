## 1. 体系概览

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **零模型依赖** | 所有测试通过 `autouse` fixture mock LLM 和 Embedding，不依赖外部模型服务 |
| **独立关注点** | 每个测试文件专注于 CA 的一条管线（C-stage / A-stage / Buffer / Store） |
| **版本路由覆盖** | v5（新 schema）和 v4（旧 schema）两条路径各自覆盖，验证向后兼容 |
| **确定性** | 用自增计数器代替 `time.time()` 生成 `api_request_id`，移除 `time.sleep` |
| **文件描述符审计** | `fd_checker` fixture 在每个测试后验证无泄漏 |

### 4.2 v5 特有的测试模式

**测试不依赖 Conftest 全局（独立性原则）**：
- Store 测试直接实例化 `SQLiteStore`，不依赖 `ca_engine`
- Buffer 测试直接调用 `_on_api_response`/`_on_pre_tool_call` 等私有方法
- PR3 注入测试直接 seed DB → 调 `assemble()` → 验证标记

**api_request_id**：当前测试使用硬编码字符串（如 `"req_001"`、`"req_e2e"`），
确定性足够且无需模块级计数器。

## 6. v5 核心测试模式

### 6.1 消息行类型速查

| 行类型 | `api_call_count` | `seq_index` | `role` | 写入方式 |
|--------|-----------------|-------------|--------|---------|
| user | 0 | 0 | user | `write_turn(role="user")` |
| assistant{tc} | N（≥1） | 0 | assistant | `write_turn(role="assistant", tool_calls_json=..., finish_reason="tool_calls")` |
| tool | N（≥1） | ≥1 | tool | `write_turn(role="tool", tool_call_id=..., status=...)` |
| final assistant | 999999 | 0 | assistant | `_run_c_stage` 自动写入 |

### 6.2 虚拟列（GENERATED ALWAYS AS）

```sql
-- 由实际列自动计算，不可 INSERT
turn_type      ← CASE WHEN role='user' OR role='assistant' THEN 'dialogue' ELSE 'tool' END
tool_sub_index ← seq_index
l2_text        ← content
```

**测试注意**：SELECT 可引用虚拟列，INSERT 不可包含它们。
旧测试 INSERT 含 `turn_type`/`tool_sub_index`/`l2_text` → v5 报 `cannot INSERT into generated column`。

### 6.3 Buffer 层数据流

```
post_api_request → ToolGroupBuffer(api_request_id)
  ↓
pre_tool_call × N → results[tool_call_id] = {status: "pending"}
  ↓
post_tool_call × N → results[tool_call_id] = {result, status, duration_ms, ...}
  ↓
flush_tool_buffer() → sort by api_call_count
  → [user row]     api=0, seq=0, role='user'
  → [assistant{tc}] api=N, seq=0, role='assistant', tool_calls_json=...
  → [tool × M]     api=N, seq=1..M, role='tool', tool_call_id=...
  → clear buffer
  ↓
process_turn_async() → _run_c_stage → write dialogue row (api_call_count=0, via backward compat default)
```

> **注意**：`api_call_count=999999` 仅用于 `_on_pre_tool_call`/`_on_post_tool_call` 的 auto-create sentinel（buffer 不存在时），
> 不在正常写入路径使用。_run_c_stage 写的对话轮行使用旧签名，自动回退到 `api_call_count=0`。

### 6.4 三级注入标记格式

```
对话轮摘要:   [~/N/0] {L1 摘要内容}
工具组摘要:   [~/N/g] 工具组：{intent}→{result}（{N}个，{state}）
工具轮摘要:   [~/N/M] {L1 摘要内容}
```

### 6.5 正则验证

```python
_CA_TAG_RE = re.compile(r'^\[~/\d+(?:/\d+|/g)?\]\s*')
# 新正则匹配三类标记：对话轮 [~/1/0]、工具组 [~/1/g]、工具轮 [~/1/5]
# 旧正则 r'^\[~/\d+/\d+\]' 不匹配工具组标记 [~/N/g]
```

## 7. 版本路由与向后兼容

### 7.1 版本判定

| 判定依据 | v4 | v5 |
|---------|-----|-----|
| `_SCHEMA_VERSION` | 4 | 5 |
| `PRAGMA user_version` | 4 | 5 |
| 主键 | `(turn_index, turn_type, tool_sub_index)` | `(turn_index, api_call_count, seq_index)` |
| 消息存储 | `l2_text` JSON 数组 | 独立列 (`role`, `content`, `tool_calls_json`) |
| ORDER BY | `turn_index ASC` | `turn_index, api_call_count, seq_index` |
| 分离方式 | `turn_type` 列 | `role` 列 |

### 7.2 Readonly 模式

```python
store = SQLiteStore(path, readonly=True)
# → 以 file:{path}?mode=ro 打开
# → 不走 WAL
# → 不启动 checkpoint 线程
# → write_turn / write_tool_group 静默跳过
```

### 7.3 向后兼容映射

```python
# write_turn 旧参数 → v5 自动映射
api_call_count == None  → 0
seq_index == None       → tool_sub_index or 0
role == None            → 'user' if turn_type == 'dialogue' else turn_type
content == None         → l2_text
```
